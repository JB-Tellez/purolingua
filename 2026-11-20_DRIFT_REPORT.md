## src/app/[lang]/rephrase/[deck]/README.md

- **[FIXED 2026-11-20: the front's "Tocca per rivelare" hint is a `<button>`; focus moves to the first answer on the flip and back to the reveal button on Flip or the next card; `.quiz-btn` no longer transitions `all` (its inherited `visibility` kept a just-revealed answer unfocusable for 0.2 s, which jsdom cannot show). Tests in `StudySession.test.tsx` and `ChoiceButton.test.tsx`; checked in Chrome with real key presses (Tab, Enter, Enter, focus on card 2's reveal button). Not checked with a screen reader.]** **The card cannot be flipped from the keyboard.** The only ways to flip a card are a click on `<div className="card-container">` (`StudySession.tsx`, `onClick={() => { if (!flipped) setFlipped(true); }}`) and a front-mic transcript that matches. That `div` has no `role`, no `tabIndex`, and no key handler, and the "Gira" button only appears once the card is already flipped. A keyboard-only user can Tab to the front's 🔊 and 🎙 buttons but never reach the answers. In browsers without `SpeechRecognition` (Firefox), where the mic is hidden, a keyboard-only user cannot use Rephrase at all. Screen readers do not announce the card as something to activate. The contract says "The user flips it" without saying how. A real `<button>` to reveal the answer on the front face (or making the front face itself a button) would fix this. That button should move focus to the choices after the flip.

## src/app/[lang]/rephrase/[deck]/README.md and src/app/[lang]/qa/[scenario]/README.md

- **[FIXED 2026-11-20: an empty start runs the same cross-deck / cross-scenario check as the end of a session, so it shows `deckComplete` / `scenarioDone` while others are due; "Study again" is hidden on either end screen when there was nothing to replay. Tests in both `*.endScreens.test.tsx`; checked in Chrome (`daily` all not due → "Mazzo completato!" with only the back button).]** **Opening a deck or scenario with nothing due says everything is done.** Both sessions show their all-done screen when the session starts with no due cards: `allDone = dueCards.length === 0 || (finished && allDecksEmpty())` in `StudySession.tsx`, with the same shape in `QAStudySession.tsx`. The cross-deck check only runs after the last card. So tapping a deck whose badge reads "Completato" shows "Hai finito per oggi! Torna domani." / "¡Terminado por hoy! Vuelve mañana.", even when other decks still have due cards. A finished scenario likewise shows "Tutti gli scenari completati!" while others are still due. The deck and scenario tiles stay links when they are done, so this is easy to reach. The contracts describe the cross-deck check only "after the last card". The only test of the empty start (`… is not offered when the session started with no due cards`, in both `*.endScreens.test.tsx`) seeds every deck or scenario as not due, so the case where others are still due is untested. Running the same check at mount (show `deckComplete` / `scenarioDone` when other decks or scenarios are still due) would fix it.

## src/app/[lang]/qa/[scenario]/README.md

- **[FIXED 2026-11-20: the auto-speak effect also runs when `finished` changes, and never speaks on an end screen. Tests in `QAStudySession.endScreens.test.tsx`.]** **Replaying a one-card session does not read the question aloud.** The question is spoken by `useEffect(() => { … speak(questionText, lang) }, [index])`. "Study again" (`resetSession`) sets `index` to 0. When the session had one due card, `index` was already 0, the effect does not run again, and the replay starts silent. Longer sessions are read aloud on replay because `index` changes. The contract says speech "runs automatically on each `index` change", which is literally true, but it does not cover this case.
- **[FIXED 2026-11-20: new `stopSpeaking()` in `src/lib/speak.ts`, called when the session unmounts. Tests in `speak.test.ts` and `QAStudySession.endScreens.test.tsx`; checked in Chrome (leaving by the back link calls `speechSynthesis.cancel()`). The Rephrase session only speaks on request, so it was left as is.]** **The question keeps playing after you leave the session.** The auto-speak effect has no cleanup, and nothing calls `speechSynthesis.cancel()` when the session unmounts. Pressing "← Torna agli scenari" while a question is being read keeps reading it over the scenario list. The contract describes when speech starts but not this. Recognition, by contrast, is cancelled on unmount (`useVoiceRecognition`). A `speechSynthesis.cancel()` cleanup when the session unmounts would make the two consistent.

## src/components/README.md

- **`MicButton` changes its name and its pressed state together.** While listening, the label switches from `study.micStart` ("Inizia a parlare") to `study.micListening` ("In ascolto…") *and* `aria-pressed` becomes `true`. A screen reader then announces something like "In ascolto…, toggle button, pressed". The pressed state already says it is on, and pressing it again does not mean "listening": it cancels. ARIA guidance for toggle buttons is to keep the name fixed and let `aria-pressed` carry the state (or to drop `aria-pressed` and keep the changing label). The contract documents both behaviours but not how they combine. Not checked with a screen reader.
